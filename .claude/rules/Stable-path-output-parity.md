## Long-stable paths need output comparison

Import, image loading, coordinate handling and the heavily used `nornir-buildmanager` paths have been
**stable in production for years**. A regression here is silently wrong science across a whole volume;
the owner reports that import problems surface quickly and visibly.

So a review finding against these paths is **weaker evidence than the code's track record**: a
long-stable path that "obviously" mishandles coordinates usually encodes a real convention (stage
coordinates and camera readout order legitimately differ from image array order).

### Required before changing these paths

- **Compare outputs before and after** on real data, not only unit fixtures: checksums or pixel-exact
  comparison where the change is meant to be behaviour-preserving; state which.
- **Add a unit test** for the fix ([`.cursor/skills/nornir-review-issue-fixing/SKILL.md`](../../.cursor/skills/nornir-review-issue-fixing/SKILL.md)).
- **Do not** "fix" an apparent axis, origin or flip inconsistency without evidence from a real file
  that the output is wrong. There is no written axis/origin contract yet
  (review [#174](https://github.com/jamesra/nornir-review/issues/174)), so a local reading cannot
  establish intent.
- **Do not regress performance**; these paths run per tile and per section.
- **A fix that changes a checksum format** (e.g. `DataChecksum` list length-prefix, binary
  `FileChecksum`, `CompressedTransformString` whitespace) invalidates checksums stored in existing
  volume metadata and triggers rebuilds of dependent stages. Say so in the commit message; see
  "Morning behavioral notes" in [`overnight-bug-review-progress.md`](../../.cursor/overnight-bug-review-progress.md).

### Comparison tools

| Script | Compares |
|--------|----------|
| `nornir-imageregistration/scripts/compare_mosaic_checksums.py` | SHA-256 of section `.mosaic` files between two build output directories |
| `nornir-imageregistration/scripts/compare_stos_checksums.py` | SHA-256 of `.stos` files between two build output directories |
| `nornir-imageregistration/scripts/diagnose_stos_orientation.py` | STOS orientation metrics (`flip_ud`, inverse-map Y correlation) per stage; flags sign flips between an input and output group |
| `nornir-imageregistration/scripts/verify_cpu_vs_batched.py` | Refined mosaic from serial vs batched (NumPy/CuPy) refine legs, plus each vs the C++ golden mosaic, within tolerance |
| `nornir-buildmanager/scripts/verify_mrc_import_parity.py` | Read-only: whether the MRC header/flip fixes can change an existing import (exit 2 when one can) |

### Test data

Real inputs beat synthesized ones here. Small real files live under `TESTINPUTPATH`
(`/nornir-testdata` in the dev container; see [nornir-docker-devcontainer](../../.cursor/skills/nornir-docker-devcontainer/SKILL.md)).
When a repro needs a production file, copy a **small** section into the test data tree; do not read
from the NAS volume in a test.
